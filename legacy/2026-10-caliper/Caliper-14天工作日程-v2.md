## 0. 怎么用这份表

**每天只做三件事**：
1. 开始前看当天的"目标"一行，确认产出物形态；
2. 结束后做**收盘三件事**：提交代码 / 写当日日志（做了什么、卡在哪、明天第一件事）/ 备份 trace；
3. 每天只允许"欠"一件事，且必须记在日志里——不允许静默延期。

**两个硬门禁**：D7 结束（基线成立？）、D14 结束（台账成立？）。门禁不过就按 §4 降级，不许硬扛。

## 2. 逐日明细

### D1 · 11-03（周二）执行器骨架
**目标**：一条命令能在容器里跑完一个任务并给出 0/1 分。

- **上午**：仓库初始化（Go module、`cmd/cal`、`internal/{runtime,gate,cap,store}` 目录）；`config.yaml` 解析；8 个子命令占位（`run/resume/trace/gate/cap/bench/report/init`）；`hyperfine` 测空壳冷启动。
- **下午**：接 Terminal-Bench 2.0——Docker 启一个任务容器 → 跑 agent loop 最小版（读任务、调模型、执行命令、判分）；跑通 1 题。
- **晚上**：写 D1 日志；把 Docker 镜像提前拉全（明天要跑 40 题）。
- **验收**：`cal bench run --task 1` → 输出 0/1 且耗时可见；冷启动 ≤80ms。
- **陷阱**：镜像拉取吃掉半天。**开工前先预拉**。

### D2 · 11-04（周三）私有任务集 40 题
**目标**：一份冻结、可复现、带验证命令的任务集。

- **上午**：定义 6 字段 schema `{id, repo, snapshot_digest, issue, verify_cmd, expect}`；写 `cal tasks lint`。
- **下午**：从自己近半年真实失败里凑 40 题（**≥10 道跨文件/文档检索题**，供 C5 用）；每题的 `verify_cmd` 必须能独立跑通。
- **晚上**：冻结 `tasks.jsonl` + `git tag tasks-v1`。
- **验收**：`cal tasks lint` 全绿；随机抽 5 题手工重跑，结果一致。
- **陷阱**：题目写得太随意 → 后面 CI 宽到没结论。宁可 40 题慢一点写。

### D3 · 11-05（周四）trace 采集
**目标**：每个任务的完整轨迹可读、可算。

- **上午**：事件结构 `{session, step, agent, tool, args, result, tokens, latency_ms, ts}`；JSONL 落地。
- **下午**：在 D1 的 loop 里埋点；跑 1 题，逐条看 trace。
- **晚上**：trace schema 写成文档；抽 3 条人工核账（step 数、token 数对得上吗）。
- **验收**：单任务 trace 字段齐全；事件计数与 loop 计数一致（无丢）。
- **陷阱**：只记 tool 不记 prompt → 后面算不了 token 税。

### D4 · 11-06（周五）存储与指标
**目标**：能从库里回答"这个 run 花了多少、成了几题"。

- **上午**：SQLite 三表（runs / traces / results）+ 索引；预留 `parent_agent_id`（为编排铺路）。
- **下午**：`cal trace cost`（先只做总 token 与步数）+ `cal bench summary`。
- **晚上**：压测 10k 事件写入，确认 p99 ≤2ms（WAL + 批量）。
- **验收**：能查出某 run 的 pass 数与总 token；写入 p99 达标。
- **陷阱**：每事件 fsync → 直接违反 NFR。**批量写**。

### D5 · 11-07（周六）统计模块
**目标**：任何数字都带区间。

- **上午**：任务级 bootstrap（按任务重抽样，**不是按 step**）；种子方差分解（任务 / 种子 / 残差）。
- **下午**：输出格式 `point [lo, hi]`；生成 Markdown 表。
- **晚上**：用 30 次重抽样验证稳定性；写"怎么读这个区间"的三行说明。
- **验收**：同一数据两次重抽样 CI 差异 <1pp。
- **陷阱**：按 step 聚类会把 CI 算窄，导致你误判"显著提升"。

### D6 · 11-08（周日）双向用例 60 条
**目标**：护栏会拦、也会放。

- **上午**：用例格式 `{id, input, expect: block|allow|text, why}`；runner。
- **下午**：写 60 条（≈30 拦 / 25 放 / 5 文本），覆盖 `rm -rf`、`git push --force`、管道执行、路径穿越、常见误伤。
- **晚上**：**故意放宽一条规则**，确认测试变红；再收紧一条，确认误伤被捕获。
- **验收**：60 条绿；放宽后至少 1 红；误报率可统计。
- **陷阱**：只写"该拦"的用例 → 护栏会越收越紧，最后把 agent 勒死。

### D7 · 11-09（周一）基线 + **Go/No-Go**
**目标**：拿到第一个可信数字，并做一次诚实的范围决策。

- **上午**：40 题 × 1 配置 × 3 seeds 跑基线。
- **下午**：出 baseline 表（成功率 + CI + 平均步数 + token + 延迟）；写方差来源分析。
- **晚上**：**Go/No-Go 决策**：哪些题不稳（抖动大）→ 标记；哪些命令脆弱 → 修或换。
- **验收**：baseline 带 CI；明确写出"继续 / 缩范围"的结论与理由。
- **陷阱**：CI 宽到 ±15pp 还硬着头皮往下走。此时应扩种子或缩题量，先修尺子。

---

### D8 · 11-10（周二）能力注册 + 矩阵 runner
**目标**：能力靠配置开关，矩阵能一键跑。

- **上午**：`capabilities/*.yaml` 解析与启停；能力接口 `Apply(ctx, session) error`。
- **下午**：矩阵 runner（能力 × seeds × 任务）；并发上限；**输入哈希结果缓存**（模型+能力集+任务+种子+版本）。
- **晚上**：复跑同矩阵验证缓存命中率。
- **验收**：一行配置切能力；复跑命中 ≥70%；单次矩阵跑完 <2h。
- **陷阱**：不做缓存 → 第二次实验就跑不动，产品会死在这里。

### D9 · 11-11（周三）闸门判定 + 台账生成
**目标**：把"值不值"变成代码。

- **上午**：三类判定函数（性能 / 安全 / 成本）+ verdict 枚举（KEEP / REJECTED / INCONCLUSIVE）。
- **下午**：`ledger.md` 生成器（表格：能力 / 默认 / Δ / 成本 / p95 / verdict / 复现命令）。
- **晚上**：造 3 组假数据（正贡献 / 负贡献 / CI 过宽）验证 verdict 正确。
- **验收**：三类假数据结论正确；台账可直接贴进 README。
- **陷阱**：把"CI 过宽"判成 KEEP。必须是 **INCONCLUSIVE → 暂不默认开**。

### D10 · 11-12（周四）C1 长规则集
**目标**：验证"规则越多越听话"是不是真的。

- **上午**：写两个 prompt 变体（长规则集 ≈120 行 vs 极简 ≈15 行），只改这一处。
- **下午**：各跑 3 seeds；采集成功率 / token / p95。
- **晚上**：写结论段落（含失败样本归类：是"没读"还是"读了没执行"）。
- **验收**：台账第 1 行有数字 + verdict；至少一条失败样本截图式引用。
- **陷阱**：顺手改了别的旋钮 → 实验作废。

### D11 · 11-13（周五）C2 延迟加载工具
**目标**：量化"工具全给"的 token 税。

- **上午**：实现 deferred tools（工具按需暴露，先给名称+一句话描述）。
- **下午**：跑对照（全量注入 vs 延迟加载），3 seeds。
- **晚上**：算 token 税与成功率差；写结论。
- **验收**：台账第 2 行；能说出省了多少 token、代价是几 pp。
- **陷阱**：延迟加载实现成"每次都要多一轮问工具" → 步数暴涨，需在结论里如实写。

### D12 · 11-14（周六）C3 自检中间件
**目标**：验证"确定性注入 > 散文要求"。

- **上午**：`PreCompletionChecklist` 中间件（退出前强制跑一遍验证清单）。
- **下午**：跑对照；观察是否有"自我确认后提前收工"的样本被拦住。
- **晚上**：写结论 + 失败模式归类。
- **验收**：台账第 3 行；若无效，明确写"无效"。

### D13 · 11-15（周日）全矩阵 + leave-one-out
**目标**：找出**零贡献 / 负贡献**的组件。

- **上午**：全矩阵复跑（缓存命中，应 <1h）
- **下午**：逐项删除实验（每个能力单独关掉跑一遍），算边际贡献。
- **晚上**：把"删了更好"的组件写进 `docs/rejected.md` 初稿。
- **验收**：≥1 条 null result 或负贡献，附数据与复现命令。

### D14 · 11-16（周一）报告与发布
**目标**：一份能直接给招聘方看的 v0.2。

- **上午**：README 首屏 = 台账（≤6 行）；`docs/rejected.md` 定稿；`cal gate report` 一键可重现。
- **下午**：录 60 秒 asciinema（`gate` 拒绝一个能力）；打 `v0.2` tag；写博客草稿（800 字）。
- **晚上**：复盘：这一段超时/欠账清单 → 调整项目 2 排期。
- **验收**：新机器按 README 三步能跑出同样的台账数字。
